# 太古仙尊每日助手

基于截图识别的安卓游戏日常自动化项目。使用 Python、ADB、OpenCV、RapidOCR 和 Tkinter，在雷电模拟器中识别页面、执行点击、确认结果，并保存当天进度。

目前维护目录为 `E:\xiuxian`，主要适配 **Windows + 雷电模拟器9 + OPPO渠道 + 720×1280竖屏**。其他渠道或分辨率需要重新验证界面和识别素材，不能直接视为兼容。

## 项目介绍

可以这样介绍这个项目：

> 我维护了一个 Python 安卓游戏日常自动化助手，通过 ADB 获取模拟器截图并执行点击，结合 OpenCV 模板匹配与 OCR 判断界面状态。项目按页面层级组织任务，支持暂停、当天断点续跑、倒计时任务收尾和资源限制，并用运行日志、截图和回归测试排查问题。

项目采用 AI 辅助开发；展示时可以结合自己实际参与的需求设计、代码修改和调试工作说明。当前属于持续适配中的个人项目，部分功能经过实机验证，部分边界情况依靠截图和模拟流程测试覆盖。

## 快速开始

1. 启动雷电模拟器，登录角色，保持游戏在前台。
2. 确认游戏截图尺寸为720×1280，并检查 `config.json` 的 ADB路径、设备和角色配置。
3. 双击桌面的“太古仙尊每日助手”，或者本目录的 `打开每日助手.vbs`。
4. 选择“全部日常”（从第一项重跑）、“继续今日日常”（读取当天断点）或单项任务，点击“开始”。

“全部日常”重新建立流程进度，从人间第一项依次执行所有任务；“继续今日日常”读取本角色当天断点，中断的任务重新检查，已结束的步骤不回头执行。任务完成时立即保存下一项位置，跨区域也能续跑。暂停保留进程，点击“继续”恢复原位置。

两种模式均保留当天已确认的购买、消耗和游戏次数记录；游戏已完成或次数用尽的任务仍按模块规则跳过，不重复购买、不增加额外次数。倒计时任务保留给自动收尾，不会让续跑跳回前面的区域。

**更换账号时，需要更新角色配置及账号标识，不能共用另一角色的进度记录。** 当前启动器里的 Python 路径也是本机路径，迁移电脑后需要修改。

## 开发环境与命令行

在 VS Code 中选择“文件 → 打开文件夹 → E:\xiuxian”，安装 Python 扩展，选择本机 Python 3.9解释器。

以下命令适用于 PowerShell，先定义解释器路径：

```powershell
Set-Location E:\xiuxian
$py = 'C:\Users\21413\AppData\Local\Programs\Python\Python39\python.exe'

# 帮助、当前任务顺序、当前画面识别
& $py .\assistant.py --help
& $py .\assistant.py order
& $py .\assistant.py inspect

# 启动图形面板
& $py .\ui.py

# 全部日常：从第一项重跑完整流程；--watch开启倒计时收尾
& $py .\assistant.py all --watch

# 继续今日日常：从当天断点继续
& $py .\assistant.py resume --watch
```

`order`、`inspect` 也会初始化ADB连接并创建运行日志，需要模拟器可连接。项目使用部分 `vendor` 依赖及本机 Python 环境，目前没有经过验证的通用一键依赖安装脚本。

调试前停止正在运行的助手，避免两个进程同时控制游戏。程序有运行锁，发现“已有助手正在运行”时应先从面板停止旧任务，不要通过删除锁文件绕过。

## 当前任务组织

四个区域固定按 **人间 → 仙界 → 虚空 → 元极** 执行。实际顺序以 `workflow.py` 为准，详细中文清单见 `任务顺序.md`，结构化清单见 `视频任务清单.json`。

| 区域 | 主要任务 |
| --- | --- |
| 人间 | 神游、圣兽预约、门派死地、药谷、普通练功与掌门传功、门派兑换、修真免费礼包、签到与抽奖、钓鱼 |
| 仙界 | 护法、课训、博戏、玉盒、参天造化露、悟道室、训话、宗门禁地、斗法、通天塔、降妖寻宝、仙猎、魔域、小世界、论剑、传功检查 |
| 虚空 | 胜境材料兑换、夜猎、仙祠指点与玄灵树、征收、观星台、夺道奖励与加速、五处供奉、游道修炼、讨伐、珍馐坊采购、赠予、钓鱼 |
| 元极 | 燃心灯收取 → 萦云楼同修领奖 → 朝会殿朝议领奖 → 御木园 |

关键规则：

- 相邻任务尽量共用父页面。例如天阙任务之间只回天阙地图，最后才回元极主界面。
- 夜猎识别已驻扎洞天，四处各15次，总计60次；有完成奖励先领取，已有倒计时则继续下一处。
- 探星分别处理夺道奖励、修炼加速；五处供奉需进入各自详情点击“领取供奉”，逐处确认与保存。
- 小世界先领奖再探索，每天最多启动三次；事件选第二项，允许材料和灵石，不花仙玉。
- 周一北京时间12点前跳过论剑；周一识别未开放提示时返回并继续下一任务。暂时跳过后再次启动会重新检查。
- 天阙同修必须点击“领取”；朝会等待文字动画出现“完成”，点击后确认奖励。当前画面优先于旧的启动记录。
- 星界运转已取消，旧命令入口仅保留兼容，不再执行点击。
- 探星禁区与星界运转已取消；旧命令保留兼容，记录取消后返回，不发送点击。探索的夺道、供奉后进入游道，看到修炼倒计时即退出。

不同模块的资源授权不同：例如小世界的材料授权不代表其他任务可以任意花费。面板中的资源开关也不是覆盖全部模块的统一预算系统，修改消耗规则前要检查对应任务代码。

## 单项调试

下列命令会真实操作游戏，也可能消耗已授权资源。排查识别问题时先用保存截图，确认后再运行单项。

```powershell
& $py .\assistant.py palace_cultivate  # 萦云楼
& $py .\assistant.py palace_court      # 朝会殿
& $py .\assistant.py palace            # 天阙四项
& $py .\assistant.py smallworld        # 小世界探索与事件
& $py .\assistant.py star_way          # 游道每日修炼
& $py .\assistant.py stars             # 夺道、加速与五处供奉
& $py .\assistant.py night             # 夜猎
```

推荐调试步骤：

1. 保存对应文件的副本，或先提交Git版本。
2. 查看最新 `logs` 子目录的 `events.txt`、`report.json` 和截图，确认实际停留页面。
3. 判断属于入口错误、识别区域遗漏、OCR误字、动画未结束、按钮未点击，还是结果确认失败。
4. 一次只修改一个原因，先运行截图/流程回归，再实机运行单项。
5. 检查次数、资源和页面变化是否符合预期，通过后再跑全部日常。

识别时常观察的变量：`body`（OCR文字）、`hits`（按钮位置）、`phase`（任务阶段）、`self.pending`（待收尾任务）、`self.ledger`（保存的当天数据）。

不要只在点击后写“成功”：应确认游戏次数变化、倒计时出现、领取按钮消失或奖励确认完成。聊天记录里的“获得奖励”不能单独证明当前有奖励弹窗。

## VS Code断点

在项目下新建 `.vscode\launch.json`，例如：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "调试朝会殿",
      "type": "debugpy",
      "request": "launch",
      "program": "${workspaceFolder}/assistant.py",
      "args": ["palace_court"],
      "cwd": "${workspaceFolder}",
      "console": "integratedTerminal",
      "justMyCode": true
    }
  ]
}
```

在代码行号旁设置断点，按F5启动。先停止面板中的任务。断点只暂停Python，**游戏动画与倒计时仍会继续**；固定截图更适合检查OCR和模板匹配。

## 进度与运行控制

- `ledgers` 中按账号保存计数和当天进度，部分有消耗的操作还会先保存提交记录，防止结果不明时重复提交。
- 不要为了重跑某项直接删除整个 `ledgers`，可能导致重复购买或消耗次数。
- 修改任务代码后“停止 → 开始”才会加载新代码；“暂停 → 继续”沿用旧进程。
- 修改 `ui.py` 后关闭面板再打开。
- 自动收尾每5分钟检查待处理项，最长24小时，跨北京时间日期会停止。
- 正常导航使用游戏内X和返回箭头；不使用安卓系统返回，以免触发OPPO退出引导。

## 版本维护与分享

建议建立Git仓库，每次提交只处理一个问题，提交说明写清“触发条件、修改行为、验证方式”。暂时保留现有开发资料，整理测试目录后再迁移样本。

对外分享前整理一份独立副本，移除个人账号配置、当天进度、运行截图和日志，替换启动器中的本机路径，并补充依赖安装说明。游戏界面和美术截图仅用于说明与识别适配，不应描述为自行创作的素材。

当前没有设置开源许可证；公开源码前需要自行选择许可证，并检查第三方依赖和素材的使用条件。

## 已知限制

- 按当前账号、渠道和720×1280界面适配，按钮位置、皮肤、文案变化可能导致识别失败。
- 仍有固定坐标和截图模板，尚不是通用安卓自动化框架。
- OCR、动画、弹窗和网络延迟可能影响结果；未确认时应保留待处理状态，结合日志检查。
- 单项验证通过不代表全部任务及所有随机事件都已实机覆盖；当前验证记录见 `验收记录.md`。
- 运行目录中保留历史配置和兼容入口；实际执行以根目录源码及当前任务清单为准。
